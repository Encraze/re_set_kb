## Cases

| Criterion | Case | Level | Data | Written by |

| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | Two concurrent first sign-ins of one subject, and a repeated one, produce a single profile holding a single member id with no display name, while different subjects receive different member ids. | unit | the compose stack's PostgreSQL with the accounts schema migrated | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | A request under `/api` with no live session is answered 401 `signed-out`, and the route behind the filter does not run. | unit | the session store faked | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | A write with a missing or wrong state-change token, or with a foreign `Origin`, is answered 403 `state-token-invalid`, and nothing changes. | unit | a live session in the faked store | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | A session idle for 30 minutes, and one opened 10 hours ago, counts as none and its row is deleted when met. | unit | the compose stack's PostgreSQL with sessions at those ages | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | `GET /api/session` with a live session answers the state-change token with `Cache-Control: no-store`. | unit | a live session in the faked store | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | The return-path check keeps a portal-relative path and turns an absolute URL, a `//` or `/\` path and a path under `/api/`, `/realms/` or `/resources/` into `/account`. | unit | none | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | Starting a sign-in stores an attempt, sets the sign-in cookie with its state and redirects to the provider's authorisation endpoint with an S256 challenge and the scope `openid` alone. | unit | the provider's metadata faked | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | Starting a sign-in while the provider does not answer within 5 seconds answers a 503 problem response and stores no attempt. | unit | a provider that times out | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | The callback with a matching state and a valid token opens a session, ensures the profile, ends the browser's old session, clears the sign-in cookie and redirects to the return path. | unit | a recorded provider exchange whose token a test key signs | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | The callback refuses an ID token with a wrong issuer, audience, expiry, nonce or signature with a 400, opens no session and logs a security event. | unit | the recorded exchange with each claim or the signature altered | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | The callback with a missing, foreign, expired or already used state starts a fresh sign-in for `/account` when the sign-in cookie is present, and answers a 400 when it is not. | unit | none | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | `GET /api/members/me` with a live session answers the display name, empty here, and the member id with `Cache-Control: no-store`. | unit | Accounts and the session store faked | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | On a 401 the API client navigates to sign-in carrying the page's path as the return value; on any other problem it shows a readable message holding the correlation id. | unit | API answers faked | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | The member layout draws nothing about the member until the member read answers, then draws the layout with the wordmark. | unit | API answers faked | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | A confirmed member who starts a sign-in through the API and enters the right e-mail address and password at the provider comes back with a session, and `GET /api/members/me` then answers their member id. | functional | the real provider with the realm import; a confirmed test member with a first and a last name | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | With no session cookie, `GET /api/members/me` and `GET /api/session` are answered 401 `signed-out`. | functional | none | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | A callback carrying a state no attempt holds, with no sign-in cookie, is answered 400 and sets no session cookie. | functional | none | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | A signed-out visitor who opens `/account` is sent to the provider's sign-in page, signs in with the right e-mail address and password, and lands on `/account` inside the member layout with the wordmark. | e2e-through-ui | the real provider with the realm import; a confirmed test member with a first and a last name | harness |
| [AC-0001-4](../../../prd/0001-members-sign-up-sign-in-and-set-the-name-other-members-see.md#acceptance-criteria) | A signed-in member who opens `/account` in a second tab sees the member layout with no second pass through sign-in. | e2e-through-ui | a member signed in through the case above | harness |
