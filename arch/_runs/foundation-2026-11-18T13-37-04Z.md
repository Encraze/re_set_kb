## Walk-through

## Choices

The Architect's first set was answered "Change some items". The Originator could not see all of it ("I only see a part of those notes. So I can't decide. It said '20 lines hidden'") and asked for the following: "let's make it simplest PoC with minimal infra and make it runnable locally. Using s3 is fine. Backend I want in Python and FastAPI. PostgreSQL is fine. The rest I don't know."

The revised set was printed in full and answered "Confirm all (Recommended)". The rounds and the gate send-back then changed several picks. Each item gives the pick as it stands and the answers that set it.

- Backend language and framework: Python 3.13 with FastAPI, from "Backend I want in Python and FastAPI" and "Confirm all (Recommended)". See [ADR 0001](../09-architecture-decisions/0001-application-stack.md), the application stack.
- Front end: a Vue 3 single-page client in TypeScript, built by Vite, with Vue Router and no component library. The server-rendered pages first confirmed were sent back at the gate ("No Jinja2 for front end. Front should stay in Vue."), and the seven-item Vue set was then answered "Confirm all (Recommended)". See [ADR 0001](../09-architecture-decisions/0001-application-stack.md), the application stack.
- Serving and API: Caddy serves the built client and routes the API path to FastAPI, which answers JSON with OpenAPI as the contract. Settled by the Vue set: "Confirm all (Recommended)". See [ADR 0001](../09-architecture-decisions/0001-application-stack.md).
- Live updates: none, because a page shows totals as they stand when it loads. Settled by the send-back: "We don't need realtime updates. An update on page refresh is good enough."
- Datastore: PostgreSQL, plus one S3 bucket for files, from "PostgreSQL is fine", "Using s3 is fine" and "Confirm all (Recommended)". See [ADR 0003](../09-architecture-decisions/0003-data-persistence.md), data persistence.
- Architectural style and modules: one application with the modules accounts, projects, participation, funding, discussion and moderation, from "Confirm all (Recommended)". See [ADR 0002](../09-architecture-decisions/0002-module-structure.md), module structure.
- Persistence tools: SQLAlchemy 2.0 and Alembic, with database-generated UUIDs and a version column, from "Confirm all (Recommended)". See [ADR 0003](../09-architecture-decisions/0003-data-persistence.md).
- Identity: self-hosted Keycloak, from "Confirm all (Recommended)". Mail uses "Mailpit stub + Gmail SMTP". The phone check is the administrator's: "Admin's manual check covers it". Sign-in stays on the server, from the Vue set's "Confirm all (Recommended)". See [ADR 0004](../09-architecture-decisions/0004-identity-provider.md), identity provider.
- Production hosting: one EC2 host running the same Docker Compose stack as a developer machine, from "Confirm all (Recommended)".
  - Local storage uses "MinIO container locally (Recommended)".
  - S3 access uses "EC2 instance role (Rec.)".
  - Releases use "Admin script, build on host (Rec.)", which replaced the earlier "GitHub Actions + GHCR (Recommended)" and "Open SSH per deploy (Rec.)".
  - Secrets: "Don't use github secrets. For now we'll go with secrets stored locally".

  See [ADR 0005](../09-architecture-decisions/0005-production-hosting.md), production hosting.
- Conventions: RFC 9457 errors, pytest, Playwright, Ruff, mypy, uv and GitHub Actions for CI, from "Confirm all (Recommended)". The front-end toolset is Node 22 LTS at build time, npm, Vitest, ESLint with Prettier and vue-tsc, from the Vue set's "Confirm all (Recommended)".
- Quality targets: none set yet, from "we skip NFRs at this stage" and "Remove them (Recommended)". The missing targets are recorded as [GAP-0001](../10-quality-requirements.md), quality targets not set. The release script and AWS resources not yet built are [GAP-0002](../08-crosscutting-concepts/delivery.md), from "Narrow claim + gap (Rec.)".
- Platforms: backend and web, from "Confirm all (Recommended)".
- UI source: generated, from "Confirm all (Recommended)".
